## Evidence and limitations

OSM is reusable under ODbL with attribution. Raw research snapshots: design/nominatim-lahore-research.json and design/osm-selected-venue-tags.json; curated import manifest: backend/data/lahore-real-venues.json. Source element identifiers are stable deduplication keys. We excluded search matches that were roads/roundabouts/open-air arts sites. Three adjacent Safari Villas badminton court features count as ONE location. Parenthetical Saddar/Johar labels disambiguate generic OSM names and are not invented business names. Sports are limited to current supported categories and evidence in OSM tags/names or the linked official site. WAPDA Sports Complex, Railway Stadium and the generically named Johar Town sports complex have no invented sports list. Additional sports, phones, operating hours, fees, amenities and photos remain unset when not independently established. No Google listing, photo, rating or review was scraped/imported.

Overpass endpoints were attempted but timed out/failed; OSM's Nominatim search and OSM element API supplied the reusable records instead. Requests were user-triggered research, serialized with delays for Nominatim, and snapshots retained instead of application-time geocoding. Official LDA, PCB, Punjab University, WAPDA and Casa pages corroborate available facts. Google Maps links on official sites were reviewed as references where accessible, but no rendered Google Maps session was available and no Google listing data was copied. Casa coordinates were explicitly embedded by its official site; they were not extracted from a Google business listing response.

## Import/deployment

Migration 202610150011_venue_directory.sql was explicitly approved by the user and applied atomically. Hosted check returned already-applied; checksum 4735181c4358b27f3b5859d78772ed3b898cd5cba0dca95d5e928fcdd3d505fb. It adds a directory source, provenance JSON and unique source index only. It preserves ownership verification constraints and does not alter booking/SSE procedures.

Commands from backend, Windows CMD:

```cmd
set NODE_ENV=development
set MAIDAAN_ENABLE_DIRECTORY_IMPORT=true
npm run directory:check
npm run directory:import
```

The development-only importer uses the existing password hashing and stable UUID convention, requires an explicit import opt-in, refuses account/source/name/location collisions, never truncates/deletes, and does not overwrite existing venue facts. Repeated imports retain the same 19 venue/account IDs. Missing researched Lahore localities are added as areas; only null area links on this import's own directory records are filled. The importer creates no courts, hours, prices, booking inventory or reviews. Subsequent authorized CRUD tests created three explicitly named FYP simulation court configurations and sample schedule prices for owners 01-03; these are hidden from public inventory and cannot accept real bookings.

## FYP manager accounts

See [LAHORE-VENUE-ACCOUNTS.md](LAHORE-VENUE-ACCOUNTS.md). These are real custom-auth development accounts, not the browser-only demo adapter. They are rejected by a production Express server. Each has one venue_managers association and no admin membership. Its account display name is FYP Venue Manager, not the real business operator. Manager venue-detail edits are stored as private simulation overrides; the public researched name/address/coordinates remain intact. These overrides and demo login names are stripped from public venue responses. Owners may add court/schedule configuration and authorized media, but directory venues retain source=directory and verified=false; public court inventory remains hidden/unbookable. This prevents simulation from becoming a real business reservation. Book the existing explicitly fictional managed fixtures for FYP booking demonstrations.

## Shared display and maps

The PostgreSQL venue directory drives public Find Venues, Leaflet, native discovery/map, details, Gemini venue searches and admin listing. Public sport filters use researched directory sports, not simulated court additions. Existing managed-court searches and bookings continue using the existing engine. OpenStreetMap attribution is visible, browser/WebView HTTP caching is retained, and there is no tile prefetch/offline downloading. [Tile policy](https://operations.osmfoundation.org/policies/tiles/). Native Leaflet JS/CSS are bundled with their BSD licence, with a controlled message bridge and authenticated data supplied by React Native; only displayed map tiles are fetched externally.
